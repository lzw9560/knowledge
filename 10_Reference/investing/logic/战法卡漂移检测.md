# 规则：战法卡漂移检测

## 规则定义

- **类型**：校验规则
- **适用实体**：[[strategies/]]（12 张战法卡）
- **严重级**：medium
- **条件**：战法卡 frontmatter 的 `source_sha` ≠ 源仓 `backend/strategies/cards/` 对应文件的当前 SHA

## 触发条件

ora-3 诊断硬事实 5：12 张战法卡是源仓（`backend/strategies/cards/`）正文逐字拷贝，无漂移检测。源仓 `cards/*.md` 一改，vault 立刻过时，且无任何检测机制（审查脚本不比对源仓）。

## 执行逻辑

```
对每张战法卡（strategies/*.md，排除 index.md）：
  1. 读取 vault 战法卡 frontmatter 的 source_sha（若未填，先回填一次）
  2. 计算源仓对应文件当前 SHA：
     git -C <Vibe-Research> rev-parse HEAD:backend/strategies/cards/<name>.md
  3. 比对：
     if vault_source_sha == source_current_sha:
       drift: false
     else:
       drift: true
       drift_detail: "源仓已变更（新 SHA: <source>），vault 待同步"
       severity: medium（报告"源已变更，vault 待同步"）
```

## 违反处置

- `action_on_violation`：标记 `drift: true` + `drift_detail`
- 报 medium 级 finding："源已变更，vault 待同步"
- 触发 [[actions/sync-from-source]]（源仓 → vault 增量同步，ora-3 D10 规划，待建）

## 前置条件

⚠️ 本规则可执行的前提是战法卡 frontmatter 已填 `source_sha` 字段。当前 12 张战法卡 frontmatter 只有 `imported_from: backend/strategies/cards/`，**无 `source_sha` 字段**——需先回填一次。

ora-3 诊断 §2.3 规划的去副本化路径：
1. 删战法卡正文的源仓拷贝
2. 改为 frontmatter 指针（`source_path` + `source_sha` + 结构化条件字段）
3. 审查脚本加第 9 项漂移检测（本规则）

当前本规则是**骨架**——回填 source_sha 后可执行比对，但战法卡正文的源仓拷贝尚未去除（去副本化是 P1，非本 P0 范围）。
