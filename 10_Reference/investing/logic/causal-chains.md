# 因果链标注规则

> 知识图谱关系深度分析层——区分**因果**与**相关**，为后续反事实推演与信号溯源提供结构化依据。

## 因果 vs 相关

图谱关系分两类：

- **因果（causal）**：A 导致 B 发生（如"政策出台 → 行业受影响"）。A 在前 B 在后，去掉 A 则 B 的发生概率显著变化。
- **相关（correlation）**：A 和 B 同时发生但无因果关系（如"两只股票同时涨停"）。可能由共同原因 C 驱动，也可能纯属巧合。

> 判据：因果需满足**时序性**（A 先于 B）+ **机制可解释**（有合理的传导路径）+ **反事实敏感**（去掉 A，B 显著不同）。三者缺一退化为相关。

## 标注方式

在实体正文的 `[[]]` 链接后加标注（保持 Obsidian 双链语义，加 ASCII 符号区分关系类型）：

### 因果链（→）

```
[[events/2026-09-07-涨停池]] → 导致 → [[stocks/003040]]
```

含义：左侧事件是右侧状态变化的原因。

### 相关链（↔）

```
[[stocks/600519]] ↔ 相关 ↔ [[stocks/000858]]
```

含义：两者同时变动，但不构成因果。

### 待验证因果链（?>）

```
[[dragon-tiger/某席位]] ?> 驱动 ?> [[stocks/000001]]
```

含义：疑似因果但尚未通过数据验证，需后续回测确认。

## 与现有逻辑规则的关系

- [[logic/confidence-decay]]：因果链的置信度随时间衰减，越久未验证的因果链置信度越低。
- [[logic/entity-lifecycle]]：因果链标注属于实体生命周期中的"关系深化"阶段。
- [[logic/报告图谱关联]]：研报到图谱的因果链需人工或 LLM 抽取，标注后进入 [[inbox/]] 待审。

## 维护约定

- 因果链标注由人工或 LLM 抽取后进 [[inbox/]] 审核，通过后才进正文。
- 待验证链（?>）在通过回测验证后升级为因果链（→），未通过降级为相关（↔）。
- 升级/降级操作记录在 [[actions/]] 下，可追溯。
