# 规则：实体改名

## 规则定义

- **类型**：自动化规则
- **适用实体**：全类型（stocks/industries/concepts/specs 等）
- **严重级**：high
- **条件**：实体文件移动或重命名时，必须用 `move_note(old, new)` 而非直接文件系统 rename

## 触发条件

实体改名场景：
- 股票改名（如 `stocks/600519.md` 重命名为 `stocks/maotai.md`）—— **不推荐**，股票应以代码为键
- spec 重新编号（如 S006 并入 S007，文件重命名）
- 文件夹结构调整（实体迁移）

## 执行逻辑

```
触发：实体改名请求
  1. 校验调用方：
     if agent 调用:
       拒绝（ora-3 §6.5：move_note 只对人工开放）
     if 人工调用:
       继续
  2. 执行 move_note(old_path, new_path):
     - 移动/重命名文件
     - 扫描全库 [[链接]]，把指向 old_path 的链接重写为 new_path
     - 处理别名（[[old|alias]] → [[new|alias]]）
  3. 记录改名日志（who/when/old/new）
```

## 违反处置

- `action_on_violation`：阻止 agent 直接文件系统 rename
- 若检测到文件被外部 rename（git diff 显示文件移动但反向链接未更新）→ 审查脚本报 broken_link（反向链接指向旧路径）

## 工具依据

- `obsidian-mcp-setup.md:97`：`move_note(old, new)` — 移动/重命名笔记（自动重写反向链接）
- `obsidian-mcp-setup.md:363`：yanxue06/obsidian-mcp 的 move_note 经 Obsidian 处理，重命名后反向链接不会断；纯文件系统直读类 server 重命名后反向链接会断
- `obsidian-mcp-setup.md:269`：要"删"笔记时，改为 move_note 移到 archive/ 文件夹（保留可恢复），而非真删

## 安全约束

ora-3 诊断 §6.5 line 929 明确：
> `move_note` 是危险操作（会重写全库反向链接），只对人工开放，agent 不可调用。

agent 若需"改名"应：
1. 在 inbox/ 建新实体
2. 提交改名请求工单
3. 人工审核后执行 move_note
