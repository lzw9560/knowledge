# 优雅降级（Graceful Degradation）

## 类别
- 容错模式（与 10_Reference/tech-learning/concepts/熔断器|[[熔断器]]、10_Reference/tech-learning/concepts/缓存策略|[[缓存策略]] 并列）
- 目标：依赖服务故障时，系统不崩，而是降级到次优但可用的状态
- 对比 fail-fast：fail-fast 直接报错，graceful-degradation 返回兜底值继续服务

## 核心策略
| 层级 | 降级手段 | 兜底来源 |
|---|---|---|
| 数据层 | 多源回退（fallback chain） | 缓存/历史快照/次优数据源 |
| 缓存层 | 熔断时返回缓存值 | 10_Reference/tech-[[learning/concepts/缓存策略|缓存]] |
| 功能层 | 关闭非核心功能，保核心 | 功能降级（如停 AI 复盘，保行情） |
| UI 层 | 标灰 + 诚实标注"数据延迟" | UI 降级（不臆造数据） |

## Vibe-Research 的五源回退
- **L1 腾讯行情**（底座层，无降级）→ **L2 东财 push2**（熔断器+push2delay降级）→ **L3 akshare/mootdx**（惰性导入，DependencyMissing 优雅报错）→ **L4 baostock/百度/新浪**（历史 K 线）→ **L5 FRED/worldmonitor**（宏观）
- 降级链示例：东财 push2 失败 → `push2delay`（延时行情）→ 路由级缓存 → 最终 UI 标灰 + "数据延迟"诚实标注
- **诚实原则**：降级不臆造数据（S130/S131/S126 lying 治理），宁可标灰不可伪造

## 与投研的类比
- 战法卡的"适用天气：晴天/阴天/雨天/暴风雨"即策略级优雅降级——市场状态差时主动降低策略激进度（仓位×0.3），而非停摆
- 10_Reference/investing/strategies/反包战法|[[反包战法]]的"炸板池 DB 缺失时整战法数据降级（不臆造候选）"即功能层降级
- 投研的"五源回退"与战法的"天气降级"同构：都是"主路径失败→次优路径→最终诚实标注"
