# 限流（Rate Limiting）

## 类别
- 分布式系统容错模式
- 目标：保护下游服务 + 遵守外部 API 配额 + 防封禁
- 与 10_Reference/tech-learning/concepts/熔断器|熔断器]] 互补：限流控入口流量，熔断器控失败后的快速失败

## 核心策略
| 策略 | 算法 | 特点 |
|---|---|---|
| 计数器 | 固定窗口计数 | 简单，窗口边界有突刺 |
| 滑动窗口 | 滑动窗口计数 | 平滑，无边界突刺 |
| 令牌桶 | 按速率发放令牌 | 允许突发（桶可攒令牌），主流 |
| 漏桶 | 固定速率漏出 | 严格匀速，无突发 |

## Vibe-Research 的 em_get 限流
- **QPS≤2**：默认 1.0s 间隔 + 0.1~0.5s 随机抖动，防被东财风控识别为机器流量
- **串行限流**：全局单队列，非并发——宁可慢不可被封
- **Session 复用**：Keep-Alive 复用连接，减少握手开销
- **直连优先**：`trust_env=False` 忽略系统代理，直连失败才降级代理
- **抖动的意义**：固定间隔易被识别为爬虫，随机抖动模拟人类行为

## 与投研的类比
- A 股的"涨跌停板"即市场级限流：单日价格变动被限制在 ±10%（科创板/创业板 ±20%），防止瞬时过度波动
- em_get 的 QPS≤2 与涨跌停板同构：都是"主动限制速率以避免系统性风险"
- 战法卡的"仓位×0.3"（10_Reference/investing/strategies/暴风雨逆势涨停|暴风雨战法]]）即策略级限流：极端天气下主动降低开仓速率
