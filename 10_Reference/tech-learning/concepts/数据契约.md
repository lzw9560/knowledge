
# 数据契约（Data Contract）

## 类别
- 架构模式（契约层 / schema-first）
- 目标：上下游通过明确的数据形状（schema）契约解耦，而非隐式约定
- 工具实现：[[10_Reference/tech-learning/frameworks/pydantic|Pydantic]]（Python）/ Zod（TS）/ Protobuf / JSON Schema

## 核心特性
- **形状即文档**：字段名 + 类型 + 单位 + 取值范围显式声明，而非散落在注释/口头约定
- **版本化**：契约可演进（v1→v2），有兼容性策略（additive 兼容 / breaking 需迁移）
- **双向约束**：生产者按契约产出，消费者按契约解析——偏离即报错而非静默 bug
- **机器可验**：契约可生成测试夹具、OpenAPI schema、TypeScript 类型（codegen）

- 契约层是 H_Reference/tech-learning/architecture/分层架构|分层架构]] 中表现层与应用层之间的 DTO 边界

## 与投研的类比
- 战法卡的 frontmatter（`type: strategy` + `edge_family` + `imported_from`）即策略级数据契约——字段显式声明，match 引擎按契约解析
- 数据源卡片的 frontmatter（`layer` + `endpoint` + `rate_limit` + `fallback`）即数据源级契约
- 投研的"字段名/单位/形状统一"与软件的"数据契约"同构：都是"形状显式声明以消除隐式约定的 bug"
