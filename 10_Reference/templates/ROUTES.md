# 提示词模板路由规则

> [!abstract] 概述
> 路由引擎的核心匹配逻辑。Agent在接收到任务后，按以下规则匹配模板。

## 一、匹配维度

路由引擎从3个维度判断该用什么模板：

| 维度 | 信号来源 | 权重 |
|------|---------|------|
| **意图关键词** | 用户输入/cron payload中的关键词 | 40% |
| **任务类型** | 任务分类（决策/分析/创作/查询/归档） | 40% |
| **情绪状态** | 用户输入的情绪强度（急/慌/冷静/无所谓） | 20% |

## 二、意图关键词匹配表

| 关键词（命中任一即触发） | 任务类型 | 模板组合 |
|--------------------------|---------|---------|
| 决策/建议/要不要/行不行/该不该/选哪个/操作 | 决策 | 防讨好 + 顾问团 |
| 分析/评估/研究/深度/拆解/复盘 | 分析 | 防讨好 |
| 头脑风暴/创意/方案/想法/可能性 | 创作 | 顾问团 |
| 归档/记录/存入/写入知识图谱 | 归档 | 无模板 |
| 查询/搜索/查一下/是什么/怎么用 | 查询 | 无模板 |
| 写代码/实现/开发/部署/脚本 | 技术 | 无模板 |
| 写作/文案/文章/内容/报告 | 写作 | 防讨好 |
| 帮我看看/你觉得/怎么看 | 轻度分析 | 防讨好 |
| 急/慌/崩了/怎么办/完蛋 | 紧急决策 | 防讨好 + 顾问团 |
| 复盘/总结/回顾/教训 | 复盘 | 防讨好 |

## 三、任务类型 × 模板矩阵

| 任务类型 | 防讨好 | 顾问团 | 两者叠加 | 无模板 |
|----------|--------|--------|---------|--------|
| 投资决策 | ✅ | ✅ | ✅ | |
| 持仓分析 | ✅ | | | |
| 突发新闻分析 | ✅ | | | |
| 知识归档 | | | | ✅ |
| 简单查询 | | | | ✅ |
| 代码实现 | | | | ✅ |
| 方案创作 | | ✅ | | |
| 复盘总结 | ✅ | | | |
| 日常闲聊 | | | | ✅ |
| 写作输出 | ✅ | | | |

## 四、情绪状态加分

| 情绪信号 | 额外动作 |
|---------|---------|
| 急/慌/焦虑 | 强制叠加防讨好，压制"安慰式回答" |
| 兴奋/乐观 | 强制叠加防讨好，压制"附和式回答" |
| 冷静/理性 | 正常路由 |
| 无明显情绪 | 正常路由 |

## 五、Cron任务路由

Cron任务在payload.message中嵌入路由指令：

```
执行XXX任务。
[ROUTE:决策] → 自动叠加防讨好+顾问团
[ROUTE:分析] → 自动叠加防讨好
[ROUTE:无] → 直接执行
```

也可以在payload中直接指定模板：

```
[TEMPLATE:防讨好专家提示词]
执行XXX任务。
```

## 六、组合执行顺序

当多个模板叠加时，执行顺序：

```
1. [防讨好专家提示词] — 设定基调（世界级专家、不讨好、不幻觉）
2. [AI顾问团提示词模板] — 设定角色（5顾问+主席）
3. [任务上下文] — 用户的实际问题/方案/数据
4. [持仓上下文] — 当前持仓信息（如涉及投资决策）
5. [市场上下文] — 当日行情/资金/事件（如涉及投资决策）
```

## 七、降级规则

1. **无匹配** → P3直接执行，不套模板
2. **模板文件不存在** → 跳过，正常执行
3. **模板组合冲突** → 防讨好优先级最高，其他按P1>P2>P3
4. **用户明确说"别废话"** → 跳过所有模板，直接给结论

## 八、新增模板流程

1. 在 `templates/` 下新建 `.md`，YAML必须含 `type: template`
2. 在本文件"关键词匹配表"和"任务类型矩阵"中添加规则
3. 在 `ROUTER.md` 路由索引中添加条目
4. 测试：用关键词触发，确认路由正确
